# 钠电与绿电的 AIDC 微电网 · 双层联合优化

> 参赛方案 **[09] 水瓶座** 的实现工作区。
> **全部结果为确定性仿真结果，非真实设备数据。**

---

## 这是什么

一个**双层优化**系统，回答两个问题：

1. **钠电如何与光伏、风电协同，为 AIDC 构建更有韧性的微电网？**
2. **在不同地区、能源条件与算力需求下，可复制的多能互补模式是什么？**

技术上分两层：

- **外层（贝叶斯优化）**：决定钠电与锂电的容量（E）与功率（P）。4–6 维低维问题。
- **内层（MILP）**：小时级调度——算力任务分配、储能充放、绿电消纳、电网购电、热泵与供热分配。

外层的四个目标：LCOE、每百万 Token 净碳排、韧性缺口、SLA 达标率。

**核心机制**：AIDC 的负荷具有双重弹性——算力侧的时间柔性（可迁移任务，等价于
"虚拟储能"）与储能侧的物理平移。二者可替代也可互补，必须**联合求解**。

**低温折减**：储能在户外集装箱布置，北方冬季 -20℃ 至 -30℃。钠电与锂电的
可用容量随温度折减，两条曲线不同——这是本方案配置结论的物理基础。

## 当前结果与结论（截至 2026-10-16）

> ⚠️ 全部为**确定性仿真结果**（非真实设备数据）；`chemistry_*.yaml` 与
> `generation.yaml` 仍含 PLACEHOLDER 占位参数，**未完成标定**。
> 因此下列"情景级发现"只陈述当前参数下的量化关系，**不是选型结论**；
> 方法层面的结论不受标定影响。完整叙述见 [`PROGRESS-REPORT.md`](./PROGRESS-REPORT.md)。

### 方法层面（已验证，不依赖参数标定）

1. **低温折减的正确建模位置是"可用能量带"，不是 SOC 动态**：γ 进动态会产生
   γ² 的凭空往返损耗（γ=0.5 时充 1 MWh 只放出 0.25）；"收缩 SOC 上界"会让
   锂电在 −25℃ 上界 ≈0.48 < 初始 0.50，**MILP 开局即不可行**。现行规格：
   SOC 窗口固定，γ 只收窄以 soc_ref 为中心的对称可用带（守门测试全绿）。
2. **大规模调度 MILP 可在实用规模内取得"认证精度"**：168 h / 2200 任务的
   S-cost 实例 34.7 s 完成，**认证全局 gap 0.2884%**——用规则排程做已验证
   上界 + 保留全部物理二元变量的辅助模型做有效下界夹逼得到，不缩短窗口、
   不截断任务、不放宽整数性与 gap 要求。
3. **韧性评估管线完整且诚实**：六类故障 × 4 配置臂 = 244 次真实故障求解 +
   84 个"未安装对应储能"的显式跳过；T_island 右删失、第一级未证明最优
   （feasible_not_proven）、N-1 通过率全部显式标注，未知保持 NaN、绝不折算为 0。
4. **单配置四目标闭环已打通（M3）**：低保真 5 代表周 → f1 LCOE / f2 碳 / f4 SLA
   （f3 = NaN 是规格要求，非缺失）；高保真 52 窗滚动年度（SOC 逐窗传递、任务
   逐窗重新生成）+ 年度故障场景 → f3（§5.4 唯一公式）。全部目标值经独立
   手算公式复核（`outputs/m3_validation/`，低保真 11/11 通过）。
5. **可复现性**：268 项验收测试（0 失败 0 跳过）、11 份 YAML SHA-256 冻结、
   单线程 + 固定种子（目标值 1e-9 / 轨迹 1e-12 复现）、逐里程碑验证脚本与
   report.json 全部入库。

### 情景级发现（依赖当前占位参数，如实列出）

- **R-NW 情景下可再生显著过配**（60 MW 装机 vs IT 基础负荷 ≈0.72 MW）：
  正常调度由**弃电惩罚主导运营成本**（A0 年化 ≈2427 万元、弃电率 81.1%）。
  储能的价值渠道是消纳盈余（A3 弃电率降至 75.0%、运营成本 ≈2255 万元），
  但当前占位造价下储能年化成本（≈399 万元/年）超过该节省 →
  A3 LCOE 1476 元/MWh **高于** A0 的 1350 元/MWh。**这不是"储能不划算"的
  结论**，是占位参数下的量化关系；标定后两侧都可能改变（§9.37：不得预设结果）。
- **f2 在 A0/A3 间无差异**（0.0287 kgCO₂/MTok）：生成数据中电网碳因子为常数
  （配置未提供波动幅度，生成器不静默发明），时段平移无减碳效果——储能的
  碳价值渠道当前未激活，如实列为标定缺口。
- **孤岛观测全部右删失**（连无储能 A0 也零失供：该周最低风光出力 4.494 MW >
  故障期最大基础需求 0.851 MW，锅炉未断）→ **f3 当前平坦，不得用于配置排序**；
  启用前须延长故障时长或标定到储能真正成为瓶颈（平坦目标比噪声目标更危险）。
- **SLA 均为 100%**（A0/A3、五周窗）：当前任务密度下无延迟，区分度待标定。
- **S-base 的政策性弃电随储能容量放大**（A0 = 0 → A1 = 2010.8 MWh/168h）：
  源于"只充到 soc_ref"的策略约束（BS3），非物理限制；跨策略比较须携带此注脚。
- 求解精度如实记录：低保真 10 窗中 9 窗认证 gap ≤1%，A3 的 W-SUM 窗为
  1.201%（60 s 预算耗尽；缓解方案：提高时限，未放宽 gap）。

## M2.5 的已实现范围

`resilience.build_scenarios` 生成六类故障，默认共 82 个等权仿真场景。
`evaluate_scenario` 调用真实故障 MILP；`aggregate_resilience` 分别报告电失供、
关键电失供、热失供、续航下界、删失率及 N-1 通过率。场景权重不是实测故障频率。
未安装对应储能的 N-1 显式跳过；未证明的续航为 NaN，不计入删失分母。

大规模正常 `S-cost`（至少 500 个任务）可先构造并验证完整整数排程，再求一个
保留全部物理二进制变量的成本下界。下界模型用必要的累计任务电量约束放宽任务时间，
其轨迹不作为调度返回。只有原模型合法整数解的上界与有效下界之间的差距达到请求值，
才报告精度达标；返回状态仍为 `feasible`，并在 `normal_bound_certificate` 记录证明。
条件物理子问题的 gap 单列，不冒充原模型 gap。小实例、其他策略及故障模式沿用原求解路径。

验算入口与逐项证据位于 `outputs/m25_validation/`。本次 R-NW 占位数据即使失电
168 小时，无储能也未失供；不能据此比较储能续航。参数尚未标定。

## M3 的已实现范围

`sizing/objective.py` 实现外层四目标的单配置闭环（`evaluate_sizing`）：

- **低保真**：5 个 168 h 代表周（含极端低温周 W-WINX），逐周用同一组生成

- **高保真**：8760 h 年度段按 §13.1 滚动时域求解（52 窗：51×168 h + 192 h，
  SOC 逐窗传递，首窗 soc(0)=soc_init、末窗 soc(T_end)=soc_init、中间窗口终端
  自由；逐窗可行性单独检查记录，首个不可行窗即停止并原样上报）+ 年度序列上
  的六类故障场景（每个场景的初始 SOC 取年度正常调度在故障起始小时的真实值），
  f3 用 §5.4 唯一公式（参考值为全局配置常数 50 MWh / 12 h）。
- **契约**：LCOE 分母是年服务电量（A0 有定义）；分子含锅炉燃料与弃电惩罚、
  不含 SLA 惩罚；内层 infeasible → 四目标 NaN（绝不为 0）；归一化范围未标定

## 最容易踩的坑

按出现频率排序。**前四条是本项目历史上真实栽过的**，请优先自查。

1. **γ 写进了 SOC 动态**。会产生 γ² 的凭空往返损耗（γ = 0.5 时充 1 MWh 只能放 0.25 MWh）。
   正确写法：**γ 只作用于可用能量带**（以 `soc_init` 为中心对称收缩），SOC 动态只含 η。
   验证：`test_cumulative_discharge_capacity_derated`、`test_charge_discharge_roundtrip_is_lossless`。

2. **能量上限漏正部截断或效率换算**。前者在越带时不可行；后者会穿过可用下界
   （η_dis = 0.9 时 `soc` 落到 0.2778 < 0.3）。
   验证：`test_energy_limits_positive_part`、`test_bus_side_limits_respect_efficiency`。

3. **用约束开关表达分配规则，或者以为不用约束也行**。供热分配必须用
   **每时段一个二进制 `y(t)`** 精确编码 `min`：
   `Q_mun_hp ≥ Q_hp − M₁·y`、`Q_mun_hp ≥ Q_mun_demand − M₂·(1−y)`，
   其中 `M₁ = max(0, U−D)`、`M₂ = D`，`U(t)` 取满载常数界（**不是逐时的** `Q_hp_max(IT_served)`）。
   `min/max` 的图非凸，写不成线性约束；**但"目标系数为正"也不能代替它**——
   后者是 v2.1 的错误，**能通过系数符号检查**（反例见 SPEC §2.4）。
   历史四版写法：反互补约束什么都没排除 → `z_boiler` 四式使分支空置 →
   "三件套"漏掉耦合项 → **v2.2 的单二进制（当前）**。
   验证：`test_heat_allocation_identities`、`test_heat_allocation_binary_present`。

3b. **目标里锅炉燃料成本或热泵电费漏项**。锅炉那条会让"少吸余热 + 多烧气"
   不受惩罚；热泵那条会**系统性偏向多开热泵**，虚高余热贡献占比。
   验证：`test_s_heat_objective_includes_boiler_cost`、`test_boiler_cost_coefficient_positive`。

4. **参数没真正生效**。写进 YAML 但没进约束 → 四个配置臂结果几乎相同。
   验证：`test_params_actually_used`（注意：A0 下储能参数不变是合法的）。

5. **PUE 被设为常数**。会抹掉温度敏感性，低温折减机制在结果中消失。
   验证：`test_pue_varies_with_temperature`。

6. **SOC 终端约束缺失**。求解器会"掏空电池"降低成本，得到不可持续的优异结果。
   验证：`test_soc_within_bounds` 的首末相等断言。

7. **热泵出力只受热源侧约束**。写成 `P_hp ≤ Q_rec/(COP−1)` 而不看接纳能力，
   零接纳画像下热量无处可去。需求侧上限同样必要。

8. **可回收余热上界受 IT 用电量约束**：`Q_hp ≤ (COP/(COP−1))·η_rec·IT_served`，
   即 `14/15 · IT_served`（**系数现算，禁止硬编码 0.9333**），满载约 4.014 MW_th——
   撑不起区域供热峰值需求。缺口由**备用热源（燃气锅炉）**补足；
   市政交付恒等式为 `Q_mun_hp + Q_boiler = Q_mun_demand`（正常模式）。

9. **配置重复定义是静默的**。YAML 重复键与跨文件同名参数**都不报错**，
   加载顺序决定取值。必须实现 `registry.yaml` 的三层检测。

10. **别把"潜在产热上界 ÷ 峰值需求"当成"余热贡献占比"**。前者可以超过 100%；
    实际占比只能在 M2 求解后从轨迹统计（`Σ Q_mun_hp / Σ Q_mun_demand`），
    且**物理上限是 100%**（因 `Q_mun_hp ≤ Q_mun_demand`），标定目标区间为 50%–100%。

11. **故障模式的"需求"与"被供"混用**。停电时仍按 `IT_load` 算制冷与余热，
    会得出"服务器没电还在发热"，虚高 `T_island` 与余热覆盖率。
    必须用 `IT_served = IT_load − it_shed`（**不是** `IT_load − unserved_elec`：
    后者是母线侧量，含 PUE 因子）。验证：`test_fault_served_load_chain`。

12. **单位双重换算**。加载层已把 `m²/kWh` 换成 `m²/MWh`，公式里再乘 1000
    → 面积需求虚高 1000 倍。**换算只发生一次，且在加载层**。
    验证：`test_unit_conversion_factor_applied`。

13. **用截断常数做硬断言**。`Q_hp ≤ 0.9333·IT_load` 会拒绝正确的满载解
    （真值 `14/15`，差 1.43e-4 MW_th）。系数一律由 `COP` 与 `eta_recovery` 现算。

## 关于参数标定

`configs/chemistry_*.yaml` 与 `generation.yaml` 中**大量数值是占位值**，
每条带 `source` 字段区分两类：

- `"PLACEHOLDER — ..."`：物理/统计形式参数，需用公开数据标定
- `"仿真设定值"`：无公开数据可标定的方案设定值

标定完成前：

- 结论只能声称"方法层面可行"，不能对外声称任何具体数值结论
- 敏感性分析必须覆盖参数区间，因为这正是占位值的替代方案

**特别提醒**：`chemistry_li.yaml` 的低温折减曲线默认比钠电更陡，
这是当前占位值的设定。标定后若该关系改变，**配置结论应相应翻转**——
这是方案设计允许的结果，不是失败。
`test_lithium_low_temp_derating_steeper_than_sodium` 会在这个关系改变时报错，
提醒同步更新结论。
